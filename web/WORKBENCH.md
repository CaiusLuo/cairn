## Data map

| Workbench area | Server surface | Data owner |
| --- | --- | --- |
| Workspace and model options | `GET /api/runtime/management?section=workbench` | Host workspace, every approved provider/group and the active selection. The picker submits a full provider/group/model selection for a Conversation Run; switching the default is `POST /api/model/select`. |
| Conversation and history | `GET/POST /api/runtime/conversations`, `GET /conversations/{id}/history`, `POST /conversations/{id}/messages` | ConversationService and DomainStore. CLI, Web and WeChat share IDs and stored history. Rename, archive and delete are available from the conversation tree. |
| Runs and execution trace | `GET /api/runtime/runs`, `GET /runs/{id}`, `GET /runs/{id}/events`, Run WebSocket | DomainStore and RunLedger. The list is bounded to the latest 100 Runs in the Server workspace. The live channel pairs preview text with ordered execution events. |
| Development Task and Worktree | `GET/POST /api/runtime/tasks`, `GET /tasks/{id}`, `GET /tasks/{id}/events`, `POST /tasks/{id}/messages` | TaskService and RuntimeCatalogue, with persisted checkpoints and existing domain projection. Task detail keeps the execution timeline and recovery review. |
| Knowledge clips | `GET/POST /api/knowledge/clips`, `GET/POST /api/knowledge/clips/{id}`, `POST /api/knowledge/clips/{id}/update|archive|unarchive`, `GET /api/knowledge/search` | Independent KnowledgeStore. The Web page pastes text or Markdown, tags and searches clips, and loads all clips 50 at a time with `limit`/`offset`; new searches and archive toggles restart at offset 0. The original text is stored verbatim with a SHA-256 digest. Create is idempotent per `request_id`, and an unconfirmed save keeps its exact request payload for retry after reload. |
| Knowledge documents | `GET/POST /api/knowledge/documents`, `GET/DELETE /{id}`, `GET /{id}/text`, `POST /{id}/retry` | DocumentStore and the Server ingestion worker. The document tab pages the library and previews extracted text. Document search combines lexical candidates with optional vectors and graph expansion. |
| Daily and weekly reviews | `GET /api/knowledge/reviews`, `POST /daily|/weekly`, `GET /{id}`, `GET /schedule`, `POST /{id}/delivery/resend`, `POST /schedule/retry`, `POST /schedule/weekly/retry` | ReviewStore under the same authenticated Web session. Knowledge → 复盘 switches between daily and weekly reports, filters by one date or ISO week, shows every version, the source manifest, saved evidence and the real delivery state, and supports manual generation and regeneration. Generation in the host timezone uses the host cutoff window, so regenerating a scheduled report supersedes it instead of creating a parallel version. Failed daily or weekly schedule periods are listed separately; “恢复调度” reuses the coordinator's explicit retry with a stable `request_id`, while “重新生成” only creates a report version. A terminal retry receipt replays the original result after a lost response. A `delivery_unknown` resend requires explicit operator confirmation. |
| Recovery review | Task/Run `GET recovery` and `POST reconcile` | Existing checkpoint review and Task sequence or Run revision. Writes require a valid operator session on the same origin or the runtime bearer. |
| Channels | `GET /api/channels`, `GET /api/channels/capabilities`, `GET /api/channels/requests/{request_id}`, `POST /api/channels/{platform}/connections`, `PATCH|DELETE /api/channels/connections/{id}`, `POST /api/channels/connections/{id}/start|stop|reconnect` | ChannelManager and ChannelStore. The independent `channels.html` page shows the six fixed platforms, then one platform page with its connection list and a right-side action menu; only `platform` lives in the URL, and create/edit/delete run in centered dialogs so refresh and history stay authoritative without a third-level page. Forms are generated from the Server-authored credential schema. Credentials are write-only, edits without new values keep the existing credential reference, and every write carries a persistent `request_id`. A lost write response retains its original intent fingerprint: an unchanged retry reuses the same ID, changed input reconciles that ID's receipt before the console accepts a new operation identity, and a completed create receipt opens the connection the Server already created instead of creating a second one. Credentials are never persisted in the browser; a cross-reload retry requires re-entering the same values. A receipt that remains pending blocks new input until its outcome can be checked. The legacy WeChat projection is `legacy-wechat`: it reads the nested `wechat` object from `management?section=wechat`, opens QR/verification and login actions in a centered dialog on the same page and is never created, edited or deleted through this page. A platform without a real adapter can save configuration but never reports running or invokes a Fake adapter. |
| Evidence drawer | Persisted Run/Task result and available tool outputs from history | Existing runtime state and Session checkpoint history. The Run drawer scopes evidence to its recorded result. |
| Settings | `/api/runtime/management` and `/api/runtime/commands` | Existing server controls for WeChat, schedules and memory. The review tab is read-only host policy: it shows daily/weekly enable state, cutoff times, timezone, authorized recipient status and the config file, and states that changes require restarting `cairn.service`. |

Paths below `/api/runtime/` in the table use that same prefix. Knowledge paths live under `/api/knowledge/` and channel paths under `/api/channels/`; both are covered by the same Web authentication and same-origin mutation checks. Submitted browser requests keep their original IDs for explicit retry after a dropped response. Unsent queue items stay in the tab. The existing page addresses share `src/main-workbench.tsx`. The shell, chat, task, run, approval, knowledge and channel views live under `src/workbench/`. The legacy Server snapshot and task-board API remain available to their existing callers.

Knowledge clips and documents are untrusted reference material. The owner can retrieve them through the Agent's read-only tools. Records and search indexes live in PostgreSQL. Private originals live under the Server runtime directory, outside the Agent workspace.

The Chat icon returns from other views to the last conversation opened in the current browser tab, even after a reload. If the tab has no remembered conversation or the Server reports it missing, the icon opens a blank chat. Clicking it in an existing conversation also opens a blank chat. Clicking it again in the blank composer keeps the draft. The sidebar's **新对话** button opens the blank composer from any view.

The former execution-graph page and its React Flow dependency were removed. Old `?view=workflow` links now land on the Development Task list, preserving their `task` parameter. LangGraph execution, Task/Run events, the execution timeline and recovery flows are unchanged.

## Browser verification

Build Web first. Run `env -u TMPDIR uv run python -m tests.support.workbench_browser --channel chrome` against the isolated fixture on macOS, or omit `--channel` after installing Playwright Chromium. The fixture starts a Server and real CLI process, forces one crash after a tool effect and verifies the recovery note and untouched artifact after another restart. Optional `--screenshots /absolute/path` saves desktop and narrow captures. The browser fixture creates WeChat-source Runs through the host API and exercises Knowledge paste, search, edit and archive against the real Web bundle, then seeds daily/weekly review versions and delivery states through the review store to exercise the review console, URL history, filters, evidence drawer, manual generation failure and the read-only review settings. It also holds a page-2 list response while switching report type and a detail response while switching review, so stale responses cannot repopulate the new view. The channel fixtures cover 0/1/N connections across the six platforms, including a Feishu create/delete flow with write-only App Secret, the three overview states, create/edit/delete, request-id replay and conflict, non-echoed credentials, lost responses with same-intent retry, changed-intent reconciliation and duplicate-free create recovery, unsupported start, mocked lifecycle reconnect, stale and overlapping poll responses, the legacy WeChat projection with a real nested management snapshot plus QR and verification prompt, refresh, Back/Forward, rapid switching, mobile layout and reduced motion. The actual Server receiver with a Fake iLink endpoint is covered by `tests/terminal/test_wechat_e2e_process.py` on Linux.

To exercise the real model path against an isolated provider-configured Server, set `CAIRN_WEB_E2E_URL`, `CAIRN_WEB_E2E_TOKEN_FILE` and `CAIRN_WEB_E2E_REAL_MODEL=1`, then run `pnpm --dir web test:e2e`. This submits one model request.
